# 关于用户归因一次讲透 - User Attribution Demystified

## Core Summary

> [!abstract] TLDR
> 用户归因是衡量推广效果与核算 ROI 的核心基础设施；Web 端主要依靠带参链接（UTM/自定义字段）与数据库多表关联，App 端则依赖广告平台设备号回传匹配或第三方归因服务。
>
> - **归因核心目的**：明确每个用户来源渠道，计算渠道注册率、付费率、留存率、获取成本与 ROI
> - **Web 端低成本方案**：通过 URL 参数（channel/position/ad_img 等）在落地页记录日志，注册时写入标签表
> - **Web 端数据表模型**：由 `user_tag`（用户标签）、`user_action`（行为记录）、`ad_cost`（广告花费）三表关联统计
> - **App 端归因差异**：应用下载断开 URL 链路，国内主要通过点击回传接口比对设备号（OAID/IDFA/IP/UA），海外依靠 AppsFlyer 等垄断服务

## Theme Analysis

### Theme 1: Attribution Purpose & Metrics Framework 归因目的与指标体系

| Dimension | Insight | Supporting Evidence |
|-----------|---------|---------------------|
| 核心价值 | 归因配合推广使用，免费与付费渠道均需精准核算 | "我们需要知道每一个用户来自于哪个渠道，进而就可以统计出每一个渠道的推广效果" |
| 关键指标 | 付费工具关注注册率、付费率、各周期留存与单客贡献 | "整理出注册率、付费率、留存率、每个注册用户平均付费金额、每个付费用户平均付费金额" |
| ROI 核算 | 付费投放必须根据每日花费反推单个渠道获客成本 | "根据每一天花费的广告费，计算每一个渠道每天的注册成本、付费用户成本、ROI" |

> [!tip]- Top 3 Actionable Recommendations
> 1. **推广前先埋归因参数**：无论免费发帖（如 V2EX/Twitter）还是付费投放，严禁使用纯裸链接，统一添加渠道标识
> 2. **建立极简三表数据模型**：设计 `user_tag`（标签）、`user_action`（行为）、`ad_cost`（成本）结构，支撑 SQL 分组统计
> 3. **以 ROI 指导预算分配**：定期复盘不同渠道的付费转化率与 LTV，向高 ROI 渠道集中倾斜资源

### Theme 2: Implementation Architectures across Web & App Web与App端实现架构

| Dimension | Insight | Supporting Evidence |
|-----------|---------|---------------------|
| Web 端机制 | URL 传参 + 落地页日志 + 注册落库用户标签表 | `https://yourdomain.com/?channel=v2ex`，将参数落库至 `user_tag` 字段 |

## PACER Application

> [!important] PACER Classification: C — Conceptual
> **Rationale**: 本文系统阐述了用户归因的底层逻辑、业务价值以及 Web 与 App 端的不同技术实现范式，属于概念与框架性知识。

### Digest Actions

核心是**概念型知识**——通过构建归因数据流网络与理解技术边界来消化。

**Core concept nodes**:
1. **渠道归因 (Channel Attribution)** — 将用户转化与特定推广来源建立因果对应关系
2. **三表分析模型 (Three-Table Model)** — 标签表、行为表、成本表构建的完整分析底座
3. **设备指纹匹配 (Device Fingerprinting)** — App 断链场景下的激活与点击概率/确定性关联

**Key connections**:
- [渠道链接参数] → [user_tag] → [user_action] 关联计算渠道转化率
- [ad_cost] + [user_action] 关联计算渠道获客成本与最终 ROI
