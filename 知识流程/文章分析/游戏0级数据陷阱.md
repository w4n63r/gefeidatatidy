# "50%角色0级"的数据陷阱 - The Data Trap Behind "50% Lv-0 Characters"

## Core Summary

> [!abstract] TLDR
> 一个看似严重的数据异常（每天大量新角色是0级），最后发现是**数据源截断**造成的假象：CP后台单文件日志最多5万条，老玩家不活跃就掉出样本，被误判为0级。
>
> - **表面结论**：0-9点进来的角色50%是0级 → 差点当成大问题排查
> - **真相**：运营每天11点拉最新5万条日志，样本被截断，最早进入的玩家被漏掉
> - **方法**：按区服分组统计 → 发现"刚开服0级最多、越往后越少" → 怀疑日志文件 → 定位截断
> - **启示**：分析异常前，先怀疑数据源/采样/截断，再怀疑业务

## Theme Analysis

### Theme 1: Data Trap 数据陷阱

| Dimension | Insight | Supporting Evidence |
|-----------|---------|---------------------|
| 表面异常 | 时间分布让人误以为是"上班时间"相关 | "每天0到9点进来的角色中有50%都是0级" |
| 真凶 | 日志文件5万条上限导致样本截断 | "每个服下载的都是最新的5万条升级日志" |
| 连锁误判 | 运营11点统计 → 结论"10点后就正常" | 统计时间与日志截断叠加出假规律 |

> [!tip]- Top 3 Actionable Recommendations
> 1. **先查数据源**：看到异常，先确认数据是否被采样/截断/去重，再怀疑业务
> 2. **分组看规律**：按区服/时间/渠道分组统计，规律往往藏在分组里
> 3. **复现与自证**：用脚本自己算一遍，别只信现成报表

### Theme 2: 排查方法论

| Dimension | Insight | Supporting Evidence |
|-----------|---------|---------------------|
| 排除法 | 先排自己的SDK，再排CP | 发行SDK前后端/其它游戏数据都正常 → 问题在别处 |
| 怀疑工具 | 数据来源本身可能是问题 | "会不会是游戏日志文件有问题" |

> [!warning]- 提醒
> 做网站/AdSense 数据分析时同样适用：GSC 数据、广告报表都可能存在口径/延迟/采样问题，先看数据口径再下结论。
