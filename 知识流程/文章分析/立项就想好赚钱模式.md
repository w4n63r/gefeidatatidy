# 立项就想好赚钱模式 - Decide Monetization at Day One

## Core Summary

> [!abstract] TLDR
> 做产品立项时就定赚钱模式：**要么收费、要么放广告，千万不要为爱发电**。用户一定会流失，别等"用户多了再变现"；同时给出游戏发行常用的投放/留存数据方法（注册成本、付费率、次留、归因上报）。
>
> - **原则**：直接向用户收费最好，次之广告费；只要有人打开就要能"揩到油"
> - **数据观**：注册率、付费率、留存率是核心指标，心中有数才知道工作重心
> - **投放方法**：几十条广告计划赛马，跟踪注册成本/付费成本/ROI，好计划加预算、差计划关停
> - **归因**：产品要对广告来源归因，上报自定义关键行为（你要什么用户就上报什么行为）

## Theme Analysis

### Theme 1: 变现前置

| Dimension | Insight | Supporting Evidence |
|-----------|---------|---------------------|
| 前置原则 | 立项就定收费模式 | "立项之初就想好赚钱模式，最好是直接向用户收费，次之是广告费" |
| 流失现实 | 用户必然流失 | "很可能等到数据库里有10万个注册用户时，已经流失了九万八千个" |
| 即时变现 | 有人打开就要能变现 | "只要有人打开了产品，我们就要能够揩到一点油" |

> [!tip]- Top 3 Actionable Recommendations
> 1. **立项三问**：谁付费？收多少？怎么收？（收费>广告>免费）
> 2. **上线即接变现**：别等"用户多了再变现"，第一天就放广告/付费入口
> 3. **建立数据仪表盘**：注册率/付费率/留存率三项起步

## PACER Application

> [!important] PACER Classification: P — Procedural
> **Rationale**: 给出立项与投放的可操作方法，属程序性知识

### Digest Actions

1. **立项检查**：给你的产品写一行"收费模式说明"（谁付费/收多少/怎么收）
2. **设指标**：把注册率/付费率/留存率记下来，上线后每周看
3. **投放练习**：如果要投放，先小额多计划赛马，再放大/关停
4. **归因准备**：确认产品能否识别广告来源并上报关键行为

### Reflection Questions

- [ ] 我的产品第一天就能变现吗？如果不能，为什么？
- [ ] 我知道自己的注册率/付费率/留存率吗？
- [ ] 我立项时，是"先做产品再想赚钱"，还是"先想赚钱再做产品"？
